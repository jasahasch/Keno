# Architecture and mathematical contract

`model.py` separates the user-authorized machine profile from the uniform 20-of-80 draw model and immutable Scenario 1 table. `generate.py` proposes indexed deterministic candidates. `canonical.py` canonicalizes incidence components under card permutation and number relabeling; literal fallback retains correctness when exact symmetry processing exceeds its budget.

`probability.py` supplies two exact algorithms. The primary enumerates number-membership regions with binomial weights. The independent evaluator enumerates actual subsets of each incidence component with bit-counted card hits. Both retain selected-number counts until the final fixed-size draw reduction. Disconnected components are combined by coefficient convolution, not by treating card results as independent. If k selected support numbers occur, outside numbers contribute C(80-u,20-k), where u is the selected union. Every marginal has total mass C(80,20) = 3535316142212174320.

The full gross law and the paying-card-count and jackpot-count laws are separate marginals. They are sufficient for the exposed metrics; a joint gross/paying/jackpot conditional-query API is not supplied. The code never multiplies those marginals as independent probabilities.

`native_backend.py` optionally recognizes isolated four-spot backbones with at most 28 remaining numbers. `native/outside.cpp` implements a region/binomial mode and a Gray-code actual-subset mode. The backbone is evaluated by distinct histogram/convolution methods. Both return all three complete marginal laws. The supplied table, including zero hits, is passed to the native program. Native work estimates, deadlines and integer mass checks prevent silent truncation. Unsupported layouts return to an explicit resource-limit outcome. This structured scope is an acceleration, not a restriction imposed on the general research universe.

`engine.py` compares all integer coefficients between evaluators. `metrics.py` independently checks expected payouts and paying counts from univariate hypergeometric identities and variance from exact pair-overlap laws. A result is accepted only after exact agreement. Arithmetic is integer/Fraction; displayed standard deviations alone use floating point. The two evaluators share the authoritative table, parsing and result serialization; agreement does not remove the need to audit those shared interfaces. Closed-form tests cover every identical-card count/spot-count combination.

`pruning.py` constructs clique groups within cards. A positive card payout forces a collision in at least one group. Its certificate independently checks this implication for every subset of each card and recomputes the union graph edge count. It applies the previously accepted clique-count lower bound for independent 20-subsets, with exact ceiling arithmetic. At K edges (K<=128), the lower expression is

    80^20 / 20! * product(1-i*(K+40)/3200, i=1..19).

Thus frequency <= (C(80,20)-ceil(expression))/C(80,20). For larger graph costs the implementation uses only the trivial bound 1. It does not resolve the outstanding graph-cost >120 research families. Special shared-pair geometries reduce constructed graph cost where verified by membership checks. Frequency bounds prune only a frequency improvement request or an incompatible jackpot frequency constraint; they never bound profitability or recovery by assumption. The mathematical dependency is the accepted `outputs/payout-frequency-proof-extension/certificate.json` and its associated report; this implementation rechecks card implications, graph construction and rational arithmetic, not the entire historical theorem derivation.

`ranking.py` performs separate exact-objective rankings and Pareto filtering. `archive.py` provides durable immutable accepted files, source ZIP snapshots, hashes and transactional SQLite indexes. Pending jobs cannot promote records. `workflow.py` connects configuration, pruning, evaluation, verification, promotion and checkpoints. `history.py` adapts old JSON formats without changing them. `cli.py` is a replaceable interface over these modules; a GUI can reuse `Research` without replacing the mathematical engine.

Limits cover component enumeration, global states, operations, elapsed time, native work and canonical permutations. General arbitrary-overlap evaluation is exponential in the worst case; no universal efficient solver is claimed. Pruning is candidate-level branch elimination, not a completed branch-and-bound proof over all compositions. Default ranks describe the verified archive only. Results do not certify machine behavior, bankroll success or global optimality.
